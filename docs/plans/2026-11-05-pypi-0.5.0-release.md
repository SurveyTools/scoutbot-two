# PyPI 0.5.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Repository rules override the skill:** no `git add` / `git commit` / `git push` / `git tag`
> steps for agents — stop at each review checkpoint with a suggested commit message. Pause for
> user approval after every task.

**Goal:** Publish `scoutbot` 0.5.0 to PyPI from SurveyTools/scoutbot-two under the OSW PyPI org
via Trusted Publishing (TestPyPI dry run first), and mark WildMeOrg/scoutbot as superseded.

**Architecture:** One new tag-triggered GitHub Actions workflow (`publish.yml`) builds once with
`uv build`, smoke-tests the built wheel in clean environments, and publishes the *same* artifacts
via OIDC: manual dispatch → TestPyPI, version tag → PyPI behind a reviewer-gated environment.
Packaging metadata is cleaned up for the PyPI page. A separate PR on WildMeOrg/scoutbot removes
its publish/Docker workflows and adds a superseded notice. The existing `0.5.0` git tag is moved
to the final merged commit, which triggers the real publish.

**Tech Stack:** setuptools (PEP 621 / PEP 639 metadata), uv, GitHub Actions,
`pypa/gh-action-pypi-publish` (Trusted Publishing), pytest.

**Spec:** No separate design doc — decisions were made in conversation on 2026-11-05 and are
recorded under *Decisions* below.

Calls made by the planner (override freely): release gate is a GitHub environment with a required
reviewer; smoke test does *not* download models (no GCS dependency in the release path); TestPyPI
dry run is triggered by `workflow_dispatch`, not by an `rc` tag; PEP 639 `license = "Apache-2.0"`;
WildMeOrg repo is otherwise left as-is (not archived).

## Global Constraints

- Run every Python tool via `uv run …` (repo rule).
- Version source of truth stays `pyproject.toml` `[project] version = "0.5.0"`; no new version string anywhere.
- Tag format: bare `X.Y.Z` (matches existing `0.5.0` tag). Publish must refuse a tag ≠ `uv version --short`.
- Supported Python: `>=3.11,<3.14` (was `>=3.10`; see D6). Smoke matrix is 3.11 and 3.13.
- Action pins follow `.github/workflows/*`: `actions/checkout@v7`, `astral-sh/setup-uv@v8.2.0`, `actions/setup-python@v6`. For actions not yet used in the repo (`actions/upload-artifact`, `actions/download-artifact`, `pypa/gh-action-pypi-publish`), look up the current release via Context7 at implementation time — do not pin from memory.
- Environments: `testpypi` and `pypi`. Artifact name: `dist`. Workflow file: `.github/workflows/publish.yml` (this exact filename is registered with PyPI — renaming it breaks publishing).
- `id-token: write` is granted **only** on the two publish jobs; workflow default is `contents: read`.

## Review Focus

1. **Tag/version mismatch** (tag pushed while pyproject says something else) → build job fails before any upload. Pinned in Task 3 Step 2.
2. **Subpackage missing from wheel** (`[tool.setuptools] packages` is a hand-written list; a new `scoutbot/<sub>/` would silently ship absent) → test fails. Pinned in Task 2 Step 1 (`test_setuptools_packages_cover_source_tree`).
3. **Wheel installs but doesn't run on the oldest / newest supported Python** → smoke job on 3.10 and 3.13 installs the wheel into a bare venv and runs the CLI. Pinned in Task 3.
4. **TestPyPI dependency confusion** (installing from TestPyPI pulls junk `numpy`/`torch` uploads) → dry-run verification downloads only the scoutbot wheel from TestPyPI with `--no-deps` and resolves deps from real PyPI. Pinned in the Release Runbook R3.
5. **Filename reuse is permanent** on both indexes: a second TestPyPI dry run of `0.5.0`, or re-publishing `0.5.0` to PyPI after a partial upload, is rejected. Runbook R3/R5 say how to retry (`0.5.0rcN` on a throwaway branch for TestPyPI; never rebuild for PyPI — rerun the failed job of the same run).

## Task 3: Publish workflow

**Files:**
- Create: `.github/workflows/publish.yml`

**Interfaces:**
- Consumes: Task 2 metadata; environments `pypi`/`testpypi` from A3; trusted publishers from A1/A2.
- Produces: workflow file name `publish.yml`, artifact `dist`, environments `pypi`/`testpypi` — the exact values registered on PyPI.

Workflow shape:

| Job | Runs when | Does |
|-----|-----------|------|
| `build` | always | checkout (no LFS), setup-uv, setup-python 3.12; **on tag push:** fail unless `"$GITHUB_REF_NAME" == "$(uv version --short)"`, with an error naming both values; `uv build`; `uvx twine check --strict dist/*`; upload artifact `dist` |
| `smoke` | needs `build`; matrix `ubuntu-latest` × Python `3.10`, `3.13` | download `dist`; `uv venv` in a temp dir (outside the checkout, so the source tree can't be imported); `uv pip install dist/*.whl`; `scoutbot --help`; `python -c` asserting `scoutbot.__version__` equals the wheel version and importing `scoutbot.loc`, `scoutbot.tile_batched`, `scoutbot.registry` |
| `publish-testpypi` | needs `smoke`; `github.event_name == 'workflow_dispatch'` | environment `testpypi`; `permissions: id-token: write`; `pypa/gh-action-pypi-publish` with `repository-url: https://test.pypi.org/legacy/` |
| `publish-pypi` | needs `smoke`; `github.event_name == 'push' && startsWith(github.ref, 'refs/tags/')` | environment `pypi` (reviewer gate); `permissions: id-token: write`; `pypa/gh-action-pypi-publish` defaults |

Triggers: `push: tags: ['[0-9]+.[0-9]+.[0-9]+*']` and `workflow_dispatch` (no inputs). Top-level `permissions: contents: read`. `concurrency: publish-${{ github.ref }}`, `cancel-in-progress: false`.
